# `src/fn` — data-last functional utilities (ruled 2026-07-18)

Ruling (Peter, 2026-07-18): inline dot-chained `.map().filter().reduce()` lambdas
are rejected — "antithetical to function composition." Prefer small named pure
functions that take values, composed through a typed `pipe`; never duplicate a
computation across two callbacks.

The module is **data-last-only helpers (always curried, one calling shape) + an
overloaded typed `pipe`**. Typing technique copied from remeda (pipe overloads +
type-guard narrowing through pipe); per-function shape copied from es-toolkit
(thin monomorphic wrappers over native `Array.prototype`, no generic dispatch).
No runtime dependencies. Ramda-style full auto-curry is rejected (untypeable).
Designed to be lifted out as its own package: zero imports from anywhere else in
SUI, no `solid-js`, no DOM — pure TypeScript.

## Phase 1 survey — the minimal set

Derived from a grep of `src/**` and `dev/showcases/workshop/jtf-tables/**`.
Only functions with **≥2 genuine call sites** ship (plus `pipe` itself). A "site"
is a chain where the functional form is a real improvement — a named projection,
a removed duplication, or a 2+ stage pipe. The hundreds of trivial single
`.map(x => <Jsx/>)` / classname `[...].filter(Boolean).join(" ")` sites are NOT
migration targets; `map`/`filter`/`join` ship because they are the composition
primitives those pipes are built from, not to rewrite every chain.

| fn | signature (data-last) | justifying sites |
|----|----|----|
| `pipe` | `pipe(value, f1, …fn)` value-first, typed | the backbone; threads types + guards |
| `map` | `map(fn) => (readonly T[]) => U[]` | composition primitive; e.g. `resolve.tsx`, `CashflowScrubChart` projections feeding `sum`/`join` |
| `filter` | `filter(pred) => (readonly T[]) => T[]`; type-guard overload narrows | `CensusView:130`, `SegmentedControl:91`, `avg.tsx:33` (`filter(isFiniteNumber)` narrows), the `(p): p is string` classname guards |
| `pluck` | `pluck(key) => (readonly T[]) => T[key][]` | `actions.tsx:58` `map(a=>a.id)`, `Select:192` `map(o=>o.label)`, `lanes.ts:58`/`DagChart` `map(n=>n.id)` |
| `prop` | `prop(key)` / `prop(key, obj)` → `T[K]` | shipped by ruling 2026-07-18 (function-first property access); see caveat below |
| `length` | `length({ length }) => number` | shipped by ruling; unary `.length` of array/string |
| `lengthOf` | `lengthOf(key)` / `lengthOf(key, obj)` = `length(prop(key, obj))` | shipped by ruling (`hits.dotChains.length`) |
| `sortBy` | `sortBy(keyFn) => (readonly T[]) => T[]` — **copies**, stable, ascending | `StatusFlowChart/columns.ts:59`, `Array.from(keys()).sort((a,b)=>a-b)` ×2 in `SwimlaneChart/layout.ts`, `ThroughputChart:129`, `ConversationTree:152`, `[...measured].sort` |

### Convention

- **Data-last, one shape.** Every helper takes its config first and returns
  `(data) => result`. There is no data-first overload (no purry). Call at a site
  directly (`sum(xs)` where the helper takes only data) or inside `pipe`.
- **Non-null input.** Helpers do NOT accept `null`/`undefined` collections —
  callers guard. Empty-array policy is per-function and documented in each file
  (`sum([]) === 0`, `mean([])` is `NaN`, `groupBy` of `[]` is an empty `Map`).
- **No mutation.** `sortBy` copies before sorting (native `.sort` mutates). This
  also fixes latent input-mutation at `ThroughputChart`/`ConversationTree`, which
  sorted their signal-derived arrays in place.

### Considered and rejected (below the bar / behavior risk)

- `max`/`min`/`maxBy`/`minBy` — the `reduce((m,v)=>Math.max(m,v), 0)` sites
  (`CashflowScrubChart:97-106`, `Chart/Axes:28`, `SwimlaneChart/helpers`) are
  **0-seeded**, so a seedless `max`/`min` would change behavior (lo clamped ≤0).
  Not worth the drift for the count. Left native.
- `prop` — was rejected here on the sortBy-argument typing ground below, but
  **shipped 2026-07-18 by explicit Peter ruling** (function-first property
  access; `prop(key, obj)` over `obj.key`, and `lengthOf` composes over it).
  The sortBy caveat still stands and is documented in `prop.ts`: as a curried
  accessor passed as an *argument* to another helper, `sortBy(prop("minWidth"))`
  types the key as `unknown` — for sort keys use a typed arrow
  (`sortBy((b) => b.minWidth)`), for array projection use `pluck`. `prop` is for
  direct/`pipe`d object access. Shipped dual-form (curried + direct).
- `length` / `lengthOf` — **shipped 2026-07-18 by ruling** (Peter flagged
  `hits.dotChains.length` in `scripts/health.mjs`). `length(xs)` is unary over
  `{ length: number }`; `lengthOf(key, obj) === length(prop(key, obj))`, dual
  form, constrained so the property at `key` has a `length`. A JS mirror lives
  at `scripts/fn.mjs` for node tooling (deleted when `fn` is extracted).
- `uniq`/`uniqBy` — `new Set(xs.map(x => x.id))` sites are membership lookups, not
  dedup-to-array. No genuine site.
- `countBy` — 1 site (`lanes.ts` `countByCol`). `partition`, scalar `clamp` — ≤1
  site each. Generic `reduce` — deliberately omitted; a data-last `reduce`
  re-invites the inline-lambda pattern the ruling rejects. Bespoke reduces
  (`choreography` weight, `ScrubChart` widest) stay native.

## Phase 2 — build `src/fn/`

- `pipe.ts` — hand-written overloads to arity ~12 + a final rest overload.
- One file per function (+ colocated `*.test.ts`): happy path, empty input,
  type-guard narrowing (compile-time asserts), `sortBy` stability + copy proof.
- `index.ts` barrel; `README.md` (convention + "liftable package" note).
- `src/index.ts`: `export * as fn from "./fn"` (mirrors the `fields` namespace).

## Phase 3 — migrate (parallel subagents, one per area)

Areas: `Table/fields` + Table; charts (Cashflow/Throughput/Chart/Swimlane/etc.);
other components (CensusView/Select/ProductGrid/…); jtf-tables bench. Replace a
chain ONLY where the functional form is a genuine improvement. Extract anonymous
inline computations into named pure fns. NEVER change behavior. Record skips.

## Phase 4 — adversarial review + full gates

`npx tsc --noEmit`; `npx tsc --noEmit -p tsconfig.dev.json | grep jtf-tables`
(empty); `npx vitest run`; `npm run build`. Reviewer checks element order, sort
copy-not-mutate, type soundness, no import cycles, module self-containment.
